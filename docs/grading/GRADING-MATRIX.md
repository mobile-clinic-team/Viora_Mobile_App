# Viora grading matrix

Audit date: 2026-09-15

Repository: `mobile-clinic-team/Viora_Mobile_App`

Observed commit: `7bbec4b` (`Initial Viora Android baseline`)

Observed branch: `main`, tracking `origin/main`

This is a baseline audit, not a grade claim. “Implemented” means the behavior is present in versioned source and is supported by a reproducible test or artifact. A contract, fixture, screen, or historical report alone does not prove production functionality. Synthetic behavior is credited as a development foundation only.

## Snapshot and evidence boundary

- The repository contains 35 Markdown documents, 123 Kotlin files, 24 JVM test files, and 7 Android test files.
- The committed project is one Android application module with `dev`, `staging`, and `prod` flavors. Current build configuration enables `devDebug` and guarded live variants; staging/prod identity and service bindings fail closed.
- The working tree is dirty: 19 tracked files are modified and 10 paths are untracked. The uncommitted changes include a patient-facing shell, role shell, route authorization, UI polish, a Phase 1 smoke test, and an untracked design image. They are recorded as worktree evidence, not committed project evidence.
- `.tools/`, `build/`, emulator files, APKs, logs, and screenshots are ignored. They can support local inspection but are not portable grading evidence until copied into a reviewed, synthetic-only evidence location and linked from a report.
- Root `docs/` is the current implementation/contract set. `docs/mobile/` contains an earlier proposed mobile migration set and now contradicts the implemented Android tree in places, including statements that no Android source or project exists. This documentation drift is a real gap.
- The current committed wrapper requests Gradle 9.6.0, while `docs/ARCHITECTURE.md` and the implementation reports describe Gradle 8.13/AGP 8.13.2. The wrapper could not complete in this audit because the sandbox could not create its external lock file and could not download the distribution. A direct cached Gradle 9.6 invocation reached dependency-accessor compilation but failed with an external cached-JAR access error. This is current verification evidence, not a source test pass.

## Conservative interpretation

The strongest defensible evidence today is the Android synthetic foundation, client architecture, contract quality, and development tests. The largest score and delivery risks are the absence of a backend/database implementation, unavailable production authentication, absence of real AI integration/safety evidence, no verified CI run or release path, and unvalidated current worktree changes. No criterion should be presented as fully complete until its missing evidence column is closed.
